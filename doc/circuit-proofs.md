# 利用者による回路の証明

利用者は NCG2 で回路を定義し、外部の Verus クレートに回路が満たすべき性質と証明を書く。core は回路データの型と、[コンパイラと VM の検証](verification.md#コンパイルの正しさ)で使う参照意味論を公開する。

## 証明対象の取り込み

ホスト側の生成ツールにプロジェクト設定と対象回路の完全修飾名を指定する。ツールは通常のコンパイラを呼び、ソース集合の確定、名前解決、マクロ展開、型・結線検査を経て、対象回路の参照ネットリストを得る。設定またはソースにエラーがあるときはコンパイラの診断を返す。

ツールは参照ネットリストを Verus の構造体と列からなる定義として生成する。ゲートと配線、ポートの名前・型・順序、ビット順を保持する。順序回路では状態素子の種類、インスタンス、初期値、公開する観測点も保持する。利用者のクレートはこの生成モジュールと core の参照意味論を参照する。ソースや設定の読み込み、定義の生成、Verus の起動はホスト側が担当し、core は `no_std + alloc` で使える。

## 組み合わせ回路の例

```lisp
(using nor)

(func inverter (in x) (out y)
  (def y (nor x x)))
```

次は、各ポートを1ビットとする最小モデルで、この `inverter` を取り込んだ例である。入力ポート、ゲート、出力ポートは、それぞれ0から添字を振る。

```rust
pub open spec fn inverter() -> FuncCircuit {
    FuncCircuit {
        inputs: seq!["x"],
        gates: seq![NorGate {
            left: Wire::Input(0),
            right: Wire::Input(0),
        }],
        outputs: seq![OutputPort { name: "y", wire: Wire::Gate(0) }],
    }
}
```

| NCG2 の記述 | Verus の定義での対応 |
| --- | --- |
| `(func inverter …)` | 回路全体を `inverter()` で参照する |
| `(in x)` | `inputs[0]` に名前 `"x"` を記録する。`Wire::Input(0)` がこのポートを参照する |
| `(nor x x)` | `gates[0]` に NOR を置き、両端を `Wire::Input(0)` に接続する |
| `(out y)` と `(def y …)` | `outputs[0]` に名前 `"y"` を記録し、右辺の NOR の出力 `Wire::Gate(0)` に接続する |

利用者は `eval_output` に入力列 `seq![x]` と出力ポートの添字 `0` を渡し、任意の入力 `x` に対して出力ポート `y` の値が `!x` になることを証明する。

```rust
pub proof fn inverter_correct(x: bool)
    ensures eval_output(inverter(), seq![x], 0) == !x,
{
    reveal_with_fuel(eval_prefix, 3);
}
```

`eval_prefix` は、最小モデルで `eval_output` が使うゲート列の評価関数である。順序回路には [tick の参照仕様](simulation.md#tick-と状態)に対応した `reset`、`step`、`observe` を用いる。例えば FIFO の仕様は、reset 直後に成立する不変条件と、許容する入力の下で各 tick がその条件を保存することから示せる。

## ソースと実行結果への接続

| 確認する関係 | 保証 |
| --- | --- |
| プロジェクトと取り込んだ定義 | 対象の完全修飾名、コンパイル設定、展開に使う `.ncg2m` を含むソース集合から生成する。いずれかが変われば定義を再生成し、証明を検査する |
| 参照ネットリストと生成定義 | 生成定義が表す回路は参照ネットリストと構造的に一致する。一致の対象は配線、ポートとビットの順序、状態素子、初期値、公開する観測点である |
| 参照ネットリストと VM | コンパイラと VM の意味保存により、`func` では合法な入力に対する出力値、`module` では reset と各 tick の観測値を一致させる |

生成物の再利用には、対象名、解決済みソース集合の内容、コンパイル設定、生成形式と意味論の版を用いる。ハッシュを使う場合は再生成の判定に用いる。回路データの一致は、生成処理の検証か、生成定義が表す構造とコンパイラ出力を照合する検査で示す。

この手順で、マクロ展開を含むプロジェクトから特定の回路を取り込み、その回路の性質を証明できる。マクロが許容される全引数に対して正しい回路を生成することは、[NCG2M の展開仕様](macros.md#展開結果の保証とテスト)を使って別に証明する。

## 実装の順序

型・結線検査とネットリスト生成に続き、小さな `func` について、ソースの選択、生成定義の照合、外部クレートでの証明までをつなぐ。`module` の状態遷移が使える段階で、reset と複数 tick の観測を扱う例を加える。
