# ソースの整形

NCG2 と NCG2M の整形ではコメント、括弧、アトムの順と原文を保ち、それらの間にある空白を統一する。整形の単位は UTF-8 のソースファイル一つとする。字句と括弧の認識には[共通の字句規則と S 式文法](grammar.md)を使う。

## 整形結果の定義

入力を字句、コメント、それらの間の空白に分ける。空白を除き、開き括弧、閉じ括弧、アトム、行コメントを入力順に並べた列を `T` とする。`T[i]` は要素の種別と元入力のバイト区間を持つ。出力に含める `T[i]` の文字列は、その区間の UTF-8 バイト列である。引用符とエスケープも元の表記を保つ。行コメントの区間に行末の CR と LF は含めない。

入力中の括弧深さを、`T[0]` の直前で 0 とする。開き括弧を通過するごとに深さを 1 増やし、閉じ括弧を通過するごとに 1 減らす。アトムと行コメントでは深さを変えない。以下の規則で使う深さ `d[i]` は `T[i]` の直前の値である。

前の要素の終端から現在の要素の始端までを、元の空白とする。`T[i]` の左に置く区切り `G[i]` は、次の表で最初に当てはまった行から決める。

| 条件 | `G[i]` |
| --- | --- |
| `i = 0` | 空 |
| 直前が行コメント、または元の空白に CR か LF がある | LF の直後にインデント |
| 直前と現在がともに行コメント以外で、`d[i] = 0` | LF 1 個 |
| 現在が行コメント | ASCII スペース 1 個 |
| 直前が開き括弧、または現在が閉じ括弧 | 空 |
| 上記以外 | ASCII スペース 1 個 |

インデントは、現在が閉じ括弧なら `2 × (d[i] − 1)` 個、それ以外なら `2 × d[i]` 個の ASCII スペースとする。開き括弧の直後に続く行コメントや閉じ括弧の後の行末コメントにも、表の順序を適用する。

`T` が空なら整形結果は空とする。それ以外では、各 `G[i]` と `T[i]` の元のバイト列を順に連結し、最後に LF を 1 個付ける。入力末尾の空白は区切りに含めない。入力中の CRLF と単独の CR は、字句間にある場合に LF にそろえる。字句間に複数の改行があっても、区切りには LF を 1 個使う。

## 例

入力では、トップレベルの二つのフォームが同じ行にあり、最後のフォームに行末コメントが付いている。

```lisp
   (using  nor) (func  gate (in x  y) (out z)
(def z   (nor x  y))   ) ; 回路の説明
```

整形後は、トップレベルのフォームを別の行に置き、元の改行の後に深さに応じた空白を入れる。

```lisp
(using nor)
(func gate (in x y) (out z)
  (def z (nor x y))) ; 回路の説明
```

## 検証する性質

- 整形結果が上の定義に一致する。入力の字句とコメントの区間が確定すれば、表は出力を一意に定める。
- 整形前後の字句とコメントは、種別、順序、元のバイト列が一致する。構文木を比較するときは、整形で移動したバイト位置を除いて比較する。
- 整形済みの出力を再び整形すると、同じバイト列になる。
- 構文エラーのあるファイルでは元入力の位置を使って診断する。上書きは文法の検査と整形が成功したときに行う。
