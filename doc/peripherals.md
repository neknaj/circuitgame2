# 標準の入出力デバイス

## デバイスの実装と接続

UART、I²C、SPI のデコードと応答、表示コントローラーの命令解釈、ボタンの入力変換は、[純粋関数型言語](macros.md)で実装し、標準ライブラリとして配布する。モデルはルートモジュールの[名前付きポート](memory-io.md#main-のポートへの割り当て)に接続する。バスプロトコルとコントローラーの命令処理を分け、I²C や SPI の受信処理を別のコントローラーでも使えるようにする。

| 標準デバイス | ルートモジュールとの接続 | デバイスが扱う値 |
| --- | --- | --- |
| ボタン・キーボード入力 | 回路入力にボタンやキーを割り当てる | 押下・解放イベントとボタン状態 |
| UART 端末 | 回路の `tx` を読み、回路の `rx` を駆動する | 受信バイト列と、端末へ入力された送信バイト列 |
| I²C キャラクター LCD | `scl`・`sda` の駆動要求と観測値を接続する | GPIO エクスパンダーの出力と文字セル。初期モデルの候補は PCF8574 と HD44780 互換の組み合わせ |
| SPI 画像 LCD | `sck`、`mosi`、`cs`、`dc`、必要に応じて `reset` や `miso` を接続する | コントローラーの命令・データ、画素メモリ。初期モデルの候補は ST7789 系の4線式シリアル接続 |

UART の設定、初期状態、イベント・通知の型は[デバイス契約の UART 例](device-contract.md#例-uart-端末)に記す。

UART はアイドルから開始ビットへの遷移を検出し、設定したビット時間に従って開始ビットとデータをサンプリングする。初版は 8N1 を対象とし、停止ビットが Low の場合はフレーミングエラーを返す。回路への送信と回路からの受信は独立に進める。端末からのテキスト入力は UTF-8 に変換し、Enter で送る改行コードは端末設定で選ぶ。テスト用にはバイト列を直接入力できる。シリアルモニターは受信バイト列を保持し、文字表示は選択した文字コードで解釈する。

I²C では各参加者について、線を Low にする出力と、合成した線の値を読む入力を用意する。前の tick で確定した駆動要求をバスがまとめ、いずれかが Low を要求した線を Low、全員が解放した線を High とする。各観測入力の駆動元はこのバス1つである。全参加者は同じ合成値を読み、今回の駆動要求を次の tick に反映する。ACK とデータのセットアップ・ホールドを表せるよう、SCL の各位相に必要な tick 数をモデルで定める。最初の互換対象は単一マスター・7ビットアドレスとし、START、STOP、バイト転送と ACK/NACK を検証する。Repeated START やクロックストレッチの対応状況はモデルごとに明記する。PCF8574 のアドレスと、出力ビットから LCD の RS・E・データ線などへの割り当てはモジュールの設定とする。

SPI は選択中のクロックエッジとデータを読み、設定した CPOL・CPHA とビット順に従ってバイトを組み立てる。LCD モデルは CS と DC から選択状態および命令・データを区別する。対応する初期化命令、画素形式、読み出し、画面のサイズやオフセットはコントローラーのモデルごとに記載する。互換性は、対象機種と対応する命令・タイミング条件で示す。回路の信号が各サンプリング時点に間に合うことを、実際の tick 列で検査する。

## 入力イベント

Web のボタン、キーボード、CLI の入力は共通のホストイベントへ変換する。ボタンの押下・解放は回路入力を更新し、パルスを出す設定ではその長さを tick で指定する。キーボードは、押下・解放をポートに割り当てる用途と、確定したテキストを UART の送信キューに追加する用途を持つ。端末へ入力した文字は UART モデルが開始ビット、データビット、停止ビットに変換し、回路の `rx` に順に出す。[外部 I/O の規則](memory-io.md#tick-ごとの受け渡し)に従って記録した入力は、画面のない環境でも再生できる。

## 実行速度

[tick 周期と実行倍率](simulation.md#tick-とシミュレーション時間)は周辺機器を含むシミュレーション全体の実行設定とする。UART のサンプル時刻や I²C の SCL 周期は tick 周期で決まる。

## 表示とオフスクリーン描画

デバイスモデルは受信バイト列、文字セル、カスタム字形、画素メモリなどを状態として管理する。表示側は確定済みの状態を読み、端末表示や画像に変換する。公開した VRAM の確定済みの内容も、表示側から読み取り専用で参照できる。回路の tick と画面の再描画は独立に進める。

Web ではシリアルモニターをテキスト UI に、LCD を Canvas に表示する。オフスクリーン描画は共通の CPU レンダラーから RGBA バッファを返す方式を基準とする。使用する色と LCD のビットマップ字形を固定すれば、GUI のない CLI や CI でも同じ画素を得られる。CLI は必要に応じて PNG を出力し、Web は RGBA を Canvas へ転送できる。Web の Worker で描画するときは `OffscreenCanvas` も使える。画素比較は共通レンダラーの出力で行う。

検証には、UART の受信・送信波形、I²C のアドレスと ACK/NACK、SPI の命令と画素書き込みの波形を使う。ポートとサンプリングの規則、プロトコルとコントローラーの状態遷移、確定した表示内容を個別に確認する。共通評価器の停止性と決定性の証明は各モデルに適用できる。実機との互換性は各モデルが対応するデータシートと入出力の trace で確認する。
