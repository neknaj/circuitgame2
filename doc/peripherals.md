# 標準の入出力デバイス

## デバイスの実装と接続

UART、I²C、SPI のデコードと応答、表示コントローラーの命令解釈、ボタンの入力変換は、[純粋関数型言語](macros.md#外付けインターフェイス)で実装し、標準ライブラリとして配布する。モデルはルートモジュールの[名前付きポート](memory-io.md#main-のポートへの割り当て)に接続する。バスプロトコルとコントローラーの命令処理を分け、I²C や SPI の受信処理を別のコントローラーでも使えるようにする。

| 標準デバイス | ルートモジュールとの接続 | デバイスが扱う値 |
| --- | --- | --- |
| ボタン・キーボード入力 | 回路入力にボタンやキーを割り当てる | 押下・解放イベントとボタン状態 |
| UART 端末 | 回路の `tx` を読み、回路の `rx` を駆動する | 受信バイト列と、端末へ入力された送信バイト列 |
| I²C キャラクター LCD | `scl`・`sda` の駆動要求と観測値を接続する | GPIO エクスパンダーの出力と文字セル。初期モデルの候補は PCF8574 と HD44780 互換の組み合わせ |
| SPI 画像 LCD | `sck`、`mosi`、`cs`、`dc`、必要に応じて `reset` や `miso` を接続する | コントローラーの命令・データ、画素メモリ。初期モデルの候補は ST7789 系の4線式シリアル接続 |

UART はアイドルから開始ビットへの遷移を検出し、設定したビット時間に従って開始ビットとデータをサンプリングする。初版は 8N1 を対象とし、停止ビットが Low の場合はフレーミングエラーを返す。回路への送信と回路からの受信は独立に進める。端末からのテキスト入力は UTF-8 に変換し、Enter で送る改行コードは端末設定で選ぶ。テスト用にはバイト列を直接入力できる。シリアルモニターは受信バイト列を保持し、文字表示は選択した文字コードで解釈する。

I²C では各参加者について、線を Low にする出力と、合成した線の値を読む入力を用意する。前の tick で確定した駆動要求をバスがまとめ、いずれかが Low を要求した線を Low、全員が解放した線を High とする。全参加者は同じ合成値を読み、今回の駆動要求を次の tick に反映する。ACK とデータのセットアップ・ホールドを表せるよう、SCL の各位相に必要な tick 数をモデルで定める。最初の互換対象は単一マスター・7ビットアドレスとし、START、STOP、バイト転送と ACK/NACK を検証する。Repeated START やクロックストレッチの対応状況はモデルごとに明記する。PCF8574 のアドレスと、出力ビットから LCD の RS・E・データ線などへの割り当てはモジュールの設定とする。

SPI は選択中のクロックエッジとデータを読み、設定した CPOL・CPHA とビット順に従ってバイトを組み立てる。LCD モデルは CS と DC から選択状態および命令・データを区別する。対応する初期化命令、画素形式、読み出し、画面のサイズやオフセットはコントローラーのモデルごとに記載する。互換性は、対象機種と対応する命令・タイミング条件で示す。回路の信号が各サンプリング時点に間に合うことを、実際の tick 列で検査する。

## 入力イベント

Web のボタン、キーボード、CLI の入力は共通のホストイベントへ変換する。ボタンの押下・解放は回路入力を更新し、パルスを出す設定ではその長さを tick で指定する。キーボードは、押下・解放をポートに割り当てる用途と、確定したテキストを UART の送信キューに追加する用途を持つ。端末へ入力した文字は UART モデルが開始ビット、データビット、停止ビットに変換し、回路の `rx` に順に出す。ホストはイベントの適用 tick と同じ tick 内での順序を記録できる。記録した入力は画面のない環境でも再生できる。

## tick とシミュレーション時間

実行設定は、1 tick が表す時間を正の有理数の ns で指定できる。時間指定を使う周辺機器を接続する場合は、この設定を必須とする。tick 0 を時刻0とし、tick `n` の終了時刻は tick 周期の `n` 倍とする。例えば tick 周期が10 ns なら、10 MHz の SPI クロックは周期10 tick、デューティ比50%なら High と Low が各5 tick になる。UART のビット時間が tick 周期の整数倍にならない場合は、有理数の位相を保ち、予定時刻以降の最初の tick 境界で信号を切り替えるかサンプリングする。各ビットを個別に丸めた時間を累積しない。要求される変化やサンプリングを区別できない tick 周期は接続時にエラーとする。I²C や SPI の入力では、回路が必要なセットアップ・ホールド時間を確保することも互換条件に含める。

### 実行速度

実行環境は tick 周期と独立に実行倍率を設定する。倍率 `m` は、実時間1秒あたりにシミュレーション時刻を `m` 秒進める目標を表す。1倍、100倍のほか、速度制限なしで実行できる。ブラウザや CLI のスケジューラが処理をまとめ、設定した倍率に合わせて待機する。実行環境の処理能力が不足する場合は、処理できる速度で各 tick を順に実行する。倍率は実行中にも変更でき、デバイスの時刻判定と確定した波形は tick 周期から求める。

例えば tick 周期10 ns で 400 kHz の I²C 波形を実行すると、SCL の1周期はシミュレーション上で2,500 ns、すなわち250 tick である。1倍でも100倍でも、I²C デバイスはこの250 tick を同じ時間として扱う。100倍の目標に届けば、シミュレーション上の1 ms を実時間10 µsで処理する。

一時停止中や、対象 tick の入力に必要なホスト応答を待っている間は論理 tick を進めない。テストやオフスクリーン描画は、応答を含む入力イベント列を与え、速度制限なしで実行できる。同じ tick 周期、初期状態、tick 付き入力イベント列であれば、実行倍率に依らず同じ trace が得られる。再現に必要な記録には tick 周期とイベントの適用 tick を含める。

## 表示とオフスクリーン描画

デバイスモデルは受信バイト列、文字セル、カスタム字形、画素メモリなどを状態として管理する。表示側は確定済みの状態を読み、端末表示や画像に変換する。回路の tick と画面の再描画は独立に進める。

Web ではシリアルモニターをテキスト UI に、LCD を Canvas に表示する。オフスクリーン描画は共通の CPU レンダラーから RGBA バッファを返す方式を基準とする。使用する色と LCD のビットマップ字形を固定すれば、GUI のない CLI や CI でも同じ画素を得られる。CLI は必要に応じて PNG を出力し、Web は RGBA を Canvas へ転送できる。Web の Worker で描画するときは `OffscreenCanvas` も使える。画素比較は共通レンダラーの出力で行う。

検証には、UART の受信・送信波形、I²C のアドレスと ACK/NACK、SPI の命令と画素書き込みの波形を使う。ポートとサンプリングの規則、プロトコルとコントローラーの状態遷移、確定した表示内容を個別に確認する。共通評価器の停止性と決定性の証明は各モデルに適用できる。実機との互換性は各モデルが対応するデータシートと入出力の trace で確認する。
