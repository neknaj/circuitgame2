# シミュレーション仕様

## tick と状態

`func` 単体は入力に対する組み合わせ結果を返す。`module` 内の `func` は基底ゲートに展開し、各ゲートを1 tick ずつ進める。配線参照、スライス、連接、フィールド参照には tick を消費しない。

以下を tick の参照仕様とする。$`S_t`$ は tick $`t`$ 終了時の内部状態、$`I_{t+1}`$ は次の tick に適用する入力フレームとする。$`S_0`$ は reset 直後の状態とし、入力とゲート出力を0、各状態素子を初期値に戻す。各 tick では同じ $`S_t`$ と $`I_{t+1}`$ からすべての更新を求め、その結果を同時に確定する。出力は確定した状態と、その tick に適用した入力フレームから読む。

```math
I_0 := \mathrm{zeroInputs}, \qquad
O_0 := \mathrm{observe}(S_0,I_0), \qquad
S_{t+1} := \mathrm{step}(S_t, I_{t+1}), \qquad
O_{t+1} := \mathrm{observe}(S_{t+1}, I_{t+1})
```

例えば NOR ゲート $`g`$ の入力参照を $`a,b`$ とすると、$`S_{t+1}[g] := \neg(\mathrm{read}(a,S_t,I_{t+1}) \lor \mathrm{read}(b,S_t,I_{t+1}))`$ とする。$`\mathrm{read}`$ は入力ポートを $`I_{t+1}`$ から、内部素子の出力を $`S_t`$ から引く。ゲートの列挙順を変えても、各更新が読む値は同じである。

外付けデバイスが入力を組み立てる順序は[外部 I/O の仕様](memory-io.md#tick-ごとの受け渡し)に従う。

## 定常状態と周期定常状態

入力フレーム $`u`$ を固定し、$`F_u(s) := \mathrm{step}(s,u)`$ とする。回路状態 $`s`$ はゲート出力、ラッチ、RAM の内容と読み出し出力を含む。比較に使う状態はこの回路の状態であり、実行環境の tick カウンターや外付けデバイスの状態は別に扱う。

- **定常状態**は $`F_u(s)=s`$ を満たす状態である。
- **周期定常状態**はある正整数 $`p`$ に対して $`F_u^p(s)=s`$ を満たす状態である。これを満たす最小の $`p`$ を基本周期と呼ぶ。定常状態の基本周期は1である。

入力を固定する直前の状態を $`s_0`$ とし、新しい入力を最初に適用した更新の直後を1 tick 経過と数える。$`s_k := F_u^k(s_0)`$ とする。固定入力を適用して $`N`$ tick 以内に、$`p`$ tick ごとに状態が戻ることの契約は次である。

```math
\forall s_0 \in \mathrm{ValidStates},\quad
\forall u \in \mathrm{Inputs},\quad
F_u^{N+p}(s_0) = F_u^N(s_0)
```

両辺に $`F_u`$ を適用する帰納法により、$`\forall k \ge N,\ s_{k+p}=s_k`$ が従う。入力が変われば、その入力に対して経過 tick を数え直す。reset があれば初期状態から再び数える。初版の契約は型と値の表現が妥当なすべての回路状態を対象とする。入力固定前の履歴によって、到達する不動点や周期軌道が異なってよい。reset から到達する状態だけを対象とする拡張では、対象状態を含む帰納的不変条件を別途証明する。

$`p`$ は繰り返しが成立する間隔を指定する。基本周期は $`p`$ の約数になり得る。例えば定常状態にも $`p=2`$ の等式が成立する。発振そのものを保証する場合は、基本周期を追加で証明する。$`s_{N+p}=s_N`$ に加え、$`p`$ の真の正の約数 $`d`$ について $`s_{N+d}\ne s_N`$ を示せば、基本周期が $`p`$ だと分かる。

公開出力が繰り返すことは、入力 $`u`$ が適用済みであれば状態の繰り返しから従う。`N=0` の場合も、入力ポートを直接公開する出力は最初の更新時に新しい入力を観測する。公開出力の一致だけを見て内部状態の繰り返しを判定することはできない。

回路から上界を求める方法と、指定した条件の検査結果は[静的解析](static-analysis.md)で扱う。

## 状態素子

ラッチの状態を $`q`$、入力を $`d`$、許可ビットを $`e`$ とする。$`e=1`$ なら $`q' := d`$、$`e=0`$ なら $`q' := q`$ とする。出力は tick 確定後の $`q'`$ である。

内蔵 RAM の各インスタンスは、アドレス幅 $`A`$ とデータ型 $`D`$ に対し、記憶内容 $`M : \{0,\ldots,2^A-1\} \to D`$ と読み出し出力 $`r : D`$ を持つ。入力はアドレス $`a`$、書き込みデータ $`d`$、書き込み許可 $`w`$ である。

```math
r' := M(a), \qquad
M'(i) :=
\begin{cases}
d & \text{if } w=1 \land i=a,\\
M(i) & \text{otherwise.}
\end{cases}
```

読み出しは毎 tick 行う。書き込み許可が1の tick は毎回書き込む。同じアドレスの読み出しには更新前の値が現れる。この動作を read-first と呼ぶ。reset は記憶内容と読み出し出力をともに初期値に戻す。初版の初期値はすべて0である。各インスタンスは独立した状態を持つ。アドレス空間と割当サイズは検査付き演算で計算し、設定した容量上限を超えた時点で診断する。

| tick 開始時の値 | tick 終了時の読み出し出力 | tick 終了時の対象語 |
| --- | --- | --- |
| アドレス3の内容が `0x12`、書き込み許可が1、書き込み値が `0x34` | `0x12` | `0x34` |
| 次の tick でもアドレス3、書き込み許可が0 | `0x34` | `0x34` |

例えばアドレス16ビット、データ32ビットの RAM は64 Ki語、256 KiBを持つ。read-first の参考は[AMD の RAM 同期モード](https://docs.amd.com/r/2025.1-English/ug901-vivado-synthesis/Block-RAM-Read/Write-Synchronization-Modes)である。

## 旧版からの移行

旧版は通常のネットリストを順に処理し、処理済みのゲート出力を同じ周回で参照する。旧版のテスト行は同じ VM 上で順に1周ずつ進む。新方式では、SR ラッチの `(q nq)` が `(1 0)` のときに `(set reset)` を `(0 1)` に固定すると、`(0 0)`、`(0 1)` と2 tick かけて遷移する。旧版の順序では1周で `(0 1)` になる。旧テストの期待値は外部から観測する時刻を明示して移行する。

## tick とシミュレーション時間

実行設定は、1 tick が表す時間を正の有理数の ns で指定できる。時間指定を使う周辺機器を接続する場合は、この設定を必須とする。tick 0 を時刻0とし、tick `n` の終了時刻は tick 周期の `n` 倍とする。例えば tick 周期が10 ns なら、10 MHz の SPI クロックは周期10 tick、デューティ比50%なら High と Low が各5 tick になる。UART のビット時間が tick 周期の整数倍にならない場合は、有理数の位相を保ち、予定時刻以降の最初の tick 境界で信号を切り替えるかサンプリングする。各ビットを個別に丸めた時間を累積しない。

通信設定から既知の変化やサンプリングを区別できない tick 周期は、接続時にエラーとする。回路が生成する I²C や SPI のエッジ間隔、セットアップ・ホールド時間は、実行中に観測した信号を使って判定する。

### 実行速度

実行環境は tick 周期と独立に実行倍率を設定する。倍率 `m` は実時間1秒あたりにシミュレーション時刻を `m` 秒進める目標を表す。tick 周期を設定した実行では、1倍、100倍などの倍率、または速度制限なしを選べる。tick 周期の指定を省略した実行では、単ステップまたは速度制限なしを選べる。ブラウザや CLI のスケジューラが処理をまとめ、設定した倍率に合わせて待機する。実行環境の処理能力が不足する場合は、処理できる速度で各 tick を順に実行する。倍率は実行中にも変更でき、デバイスの時刻判定と確定した波形は tick 周期から求める。

例えば tick 周期10 ns で 400 kHz の I²C 波形を実行すると、SCL の1周期はシミュレーション上で2,500 ns、すなわち250 tick である。1倍でも100倍でも、I²C デバイスはこの250 tick を同じ時間として扱う。100倍の目標に届けば、シミュレーション上の1 ms を実時間10 µsで処理する。

一時停止中や、適用 tick が指定されたホスト応答を待っている間は論理 tick を進めない。テストやオフスクリーン描画は、応答を含む入力イベント列を与え、速度制限なしで実行できる。同じ回路とデバイス構成、初期状態、tick 周期、[適用順を記録したイベント列](memory-io.md#tick-ごとの受け渡し)から、実行倍率に依らず同じ trace が得られる。
