# 純粋関数型言語の仕様

## 方針

マクロ、外付けインターフェイス、プロパティテストで、同じ純粋関数型言語を使う。マクロは構文を受け取って構文を返す。外付けインターフェイスは回路の入出力とホストのデバイスをつなぐ状態遷移を記述する。有限リストや自然数に対する反復を備え、型検査と循環検査を通った関数の停止性を、ステップ数に上限を置かない意味論で示す。実行は複数の枠に区切り、ホストが区切りごとに中断要求を確認する。LispKit Lisp は S 式や関数によるリスト処理の参考とする。

## 初版の構文

`.ncg2m` の宣言 `defmacro` で変換器を定義し、`func`、`module` または `module-part` の本体で `expand` を呼ぶ。引数は呼び出し側の構文オブジェクトとして渡す。変換器は `def` に展開できる構文の有限リストを返す。空のリストも有効とする。初版の展開先は回路本体とし、生成結果に含まれる `expand`、`use`、`namespace`、`defmacro` を拒否する。挿入した引数の断片にも同じ規則を適用する。

`defmacro` の本体はマクロ段階の式として解析する。補助関数、データ型、式の型検査、段階ごとに公開する名前は[関数型言語の構文と型検査](functional-types.md)を参照する。

`circuitgame2.toml` の `sources` に `logic.ncg2m` と `main.ncg2` を指定する。

`logic.ncg2m`

```lisp
(namespace logic
  (export double-invert)
  (defmacro double-invert (output input)
    (list
      (syntax (def tmp (nor (unsyntax input) (unsyntax input))))
      (syntax (def (unsyntax output) (nor tmp tmp))))))
```

`main.ncg2`

```lisp
(using nor)

(module main (in x tmp) (out y z)
  (expand ::logic::double-invert y x)
  (expand ::logic::double-invert z tmp))
```

`syntax` は構文オブジェクトを1つ返す。`list` は同じ型の値を引数順に集めたリストを返し、この例では構文オブジェクト2個のリストになる。同じ変換器の呼び出しで生成したテンプレート間では、導入した束縛を共有して解決する。2回の展開は、それぞれ独立した一時配線 `tmp` を導入する。2回目の `input` に渡す `tmp` は入力ポートを指す。出力先の `y` と `z` は呼び出し元が与えた公開名である。

テンプレート内の `nor` は、展開した回路の検査で、プロジェクトが `(using nor)` で指定した基底ゲートに解決する。

## 純粋関数と構造的な反復

初版の値は真偽値、チェック付き整数、自然数、シンボル、有限リスト、構文などのデータとする。名前付き補助関数、`let`、`if`、リストの構築と分解、比較、算術、構文の分解とテンプレートを提供する。関数の引数は左から右へ評価し、`if` は選択した分岐だけを評価する。値は不変とし、ホスト I/O、暗黙の乱数、ユーザー定義の再帰、動的な関数呼び出しや `eval` を組み込みに含めない。関数の引数をデータに限定する一階の言語として始める。再帰が必要な処理には、次の反復を用意する。

| フォーム | 評価規則 |
| --- | --- |
| `(fold-list xs init (item acc) body)` | `xs` と初期値を一度評価し、固定したリストを先頭から処理する。反復ごとに要素と現時点の累積値を本体へ束縛する |
| `(fold-nat n init (index acc) body)` | `n` と初期値を一度評価し、固定した自然数 `n` に対してインデックス0から `n-1` まで同じように処理する |

累積値と本体の結果には同じ型を要求する。累積値にリストや構文を追加しても反復対象は変わらない。例えば、幅を表す構文から自然数を取り出し、その幅の回数だけ結線を作れる。整数の表現範囲を超える演算や、想定と異なる構文を分解する操作は定義済みのエラーを返す。

## テンプレートと束縛

`syntax` はリテラルの識別子に定義位置とスコープを付ける。`unsyntax` は評価した構文オブジェクトを1つ、`splice` は構文オブジェクトのリストをテンプレートに挿入する。挿入した断片は元のスコープと位置を保持する。`nat-syntax` が生成した構文も展開元を記録する。呼び出し元の名前へ接続する場合は、名前を引数として受け取る。引数の名前を `def` の束縛位置に挿入すると、呼び出し側の回路の局所信号を定義する。この名前は展開後の名前収集で登録し、他の本体断片からも参照できる。

テンプレート中の参照は定義側の束縛を使う。宣言の別名は定義位置の `use` で元の宣言に解決し、挿入した断片は元の参照先を保つ。テンプレートが導入するローカル名には展開ごとに新しい束縛 ID を割り当て、導入した参照と対応させる。型・結線検査は文字列に加えて束縛 ID を扱う。生成された構文の診断には呼び出し位置を示し、必要に応じて定義側のテンプレートや入力断片の位置を併記する。

## 停止性とコンパイラの接続

1. [共通の規則](names.md)でソース集合、宣言表、別名を確定し、補助関数の呼び出しグラフを作る。反復の本体にある呼び出しも含め、循環を型検査段階で拒否する。
2. 値・エラーを返す評価の参照仕様を定義し、受理された式に有限の評価導出があることを Verus で証明する。補助関数の呼び出しはグラフ上の順位を下げ、部分式の評価は構文の大きさを減らす。各反復は未処理の要素数または残りの回数を減らし、その本体は独立に停止する。
3. 展開器は元の有限な構文木にある `expand` を正規化済み仮想パスとファイル内の位置の順に処理する。生成結果は `def` の列として検査し、新たな展開箇所が増えないことを示す。受理した構文は幅・型、名前解決、単一駆動など通常の回路検査に渡す。

評価器では、定義済みエラーを含めて有限回の遷移で最終状態に達することを示す。証明は、受理可能な入力に対する有限な参照評価を構成し、各実装遷移との対応を示してつなぐ。ホストに実行に必要なメモリがあることは、この意味論の適用条件とする。有限なリストへの反復でも生成物は大きくなり得るため、実行には次節の中断点を設ける。

## 一時停止、再開、中断

評価器と展開器は、継続、環境、反復の位置、構築中の結果、次に割り当てる束縛 ID を明示的な状態として保持する。`run_slice(state, fuel)` は正の `fuel` を受け取り、指定した回数まで遷移して、完了、評価エラー、または再開可能な状態を返す。fuel を使い切った時点で処理が残っていれば、一時停止して次の実行枠を待つ。この API は純粋関数の評価とマクロ展開に使う。入力のパースや通常の型検査はそれぞれの API で扱う。

CLI と言語サーバーは枠の間で中断要求を確認する。Web は枠の間にブラウザのイベントループへ制御を返す。中断を受けたらホストは再開状態を破棄し、中断を通知する。編集によって文書バージョンが変わった場合も旧状態を破棄する。確定した展開結果だけをコンパイラと LSP に渡す。長いリストの走査や大きな構文の連接は複数の遷移に分ける。ステップ数の保証は経過時間の保証と区別する。

Verus では、実行枠が指定したステップ数を超えないこと、一時停止から正確に再開できること、実行枠の分け方が値、診断、生成された束縛に影響しないことを示す。例えば中断なしで `a` ステップと `b` ステップに分けた実行は、`a+b` ステップをまとめて実行したときと同じ状態または最終結果を返す。この性質と、実装の遷移が有限の参照評価を進めるという証明から、正の実行枠が継続して与えられる実行はいずれ完了する。

形式仕様では、受理された式と環境から得られる初期評価状態を $`s_0`$、評価機械の1ステップを $`\mathrm{next}`$ とする。値またはエラーに到達した最終状態では $`\mathrm{next}(s) := s`$ と定める。$`R_n(s) := \mathrm{next}^{n}(s)`$ とすると、示すべき性質は次のとおりである。

```math
\begin{aligned}
&\forall s_0 \in \mathrm{AcceptedInit},\quad
  \exists n \in \mathbb{N},\ \mathrm{Final}(R_n(s_0)),\\
&\forall s \in \mathrm{Reachable},\ \forall a,b \in \mathbb{N},\quad
  R_b(R_a(s)) = R_{a+b}(s).
\end{aligned}
```

`run_slice` の返り値は、この状態が最終状態か途中状態かに対応する。中断した実行は、評価の返り値を公開する前にホストが破棄する。内部バッファの最適化は、対応する参照状態と同じ値、診断、生成された束縛を得ることを条件とする。

実行枠の合成は $`b`$ に関する帰納法で従う。$`b=0`$ では $`R_0`$ が恒等関数であり、$`b+1`$ では帰納法の仮定の両辺に $`\mathrm{next}`$ を適用する。実装の証明では、実行枠の処理がこの反復に対応することを示す。

## 展開結果の保証とテスト

展開の成功結果は、その位置で許された本体フォームだけを含み、各位置情報が入力断片または展開元に対応する。挿入した参照は元の束縛を保持し、テンプレートが導入した束縛は呼び出し元の同名束縛と衝突しない。生成された回路が型・結線検査を通れば、[コンパイルの正しさの定理](verification.md#コンパイルの正しさ)を適用できる。例えば生成された任意幅の加算器が整数加算を実装することは、その生成器について個別に証明できる。

プロパティテストも共通の評価器を使う。テスト段階に限り、コンパイル済み回路と有限の入力列を受け取り、出力 trace を返す操作を提供する。seed と PRNG の状態を明示し、方式とケース順を固定する。失敗時は入力列、失敗 tick、使用した seed を保存する。
