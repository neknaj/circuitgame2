# 外付けデバイスの初期化とホスト境界

## デバイス種別とインスタンス

[実行設定](project-config.md)の `device.name` はインスタンスを、`device.kind` は登録したデバイス種別を指定する。種別には、ポートの型と方向、オプションの型と検査規則、状態型、利用可能なイベント・要求とその型を記述する。標準デバイスの種別はホストが登録する。ユーザー定義の関数は、この記述に対応する入口として登録できる。同じ種別を複数接続した場合も、状態とイベント列はインスタンスごとに分かれる。

入力値や発行可能な要求は、デバイス種別に登録した型と操作で決まる。ユーザー定義関数は要求をデータとして返し、ファイルや画面の操作はホストが実行する。

## 初期化とリセット

```text
init(Options, InitContext) -> Result<State, InterfaceError>
reset(State, Options, InitContext) -> Result<State, InterfaceError>
```

`InitContext` は設定した tick 周期と初期化先の reset 世代を含む。起動時はポート接続とオプションを検査し、すべてのデバイスの `init` が成功した時点で初期状態を確定する。初期化関数は純粋であり、ホスト要求を発行しない。最初に回路へ駆動する値は第1 tick の `step` で決める。回路の tick 0 における入力と出力は[シミュレーション仕様](simulation.md#tick-と状態)に従う。

reset を受け付けたときに進行中の tick があれば破棄し、最後に確定した状態から各デバイスの `reset` を評価する。省略した場合は同じ設定で `init` を評価する。全デバイスが成功したときだけ、新世代と回路・デバイスの初期状態を一括確定する。失敗時は直前の確定状態、世代、イベント列を使う。成功時は旧世代の入力待ち列、未着の応答、保持中の応答を新世代の `step` へ渡さない。ホスト上の永続データは回路の reset を越えて保持する。初期化や reset の失敗は構造化した診断として報告する。

## イベント、要求、応答

デバイスが受け取るイベントは、外部から与えた入力と、発行済みの要求への応答に分ける。

```text
HostEvent = Input(InputPayload)
          | Response(LocalTag, Result<ResponsePayload, HostIoError>)
HostRequest = Notify(NotificationPayload)
            | Request(LocalTag, RequestPayload)
```

各 payload の型と、対応する要求・応答の組はデバイス種別が定める。`Notify` は応答を待たない通知、`Request` は成功または失敗の応答を1個待つ操作である。`LocalTag` はデバイスが付ける識別子で、同じインスタンスの tick 開始時点で未応答の要求と、その tick の新規要求の間で重複できない。応答を消費したタグは次の tick から再利用できる。ホストは要求を確定する際、インスタンス ID、reset の世代、世代内の通し番号から一意な要求 ID を割り当てる。応答はその ID で照合してから、デバイスのタグを付けて配送する。対応する要求がない応答、重複応答、旧世代の応答、payload の型が違う応答はデバイスの入力列に入れず、ホスト側の診断として扱う。

複数のインスタンスが同じ tick に要求を返した場合は、実行設定に並んだインスタンスの順、各インスタンスのリスト順で取り次ぐ。確定前の失敗や中断時は[外部 I/O の確定規則](memory-io.md#外付けインターフェイスの関数)に従う。再生モードは記録から入力・応答・reset を供給する。生成した要求列は記録の照合に使い、再生中は外部操作を再実行しない。

## 例 UART 端末

`uart-terminal` は回路の `tx` を観測し、回路の `rx` を駆動する。両ポートの型は1ビットとする。初版のオプションは正の整数の `baud` で、フレーム形式は 8N1 とする。接続時に tick 周期が指定されていることと、既知のビット時間を[シミュレーションの時間規則](simulation.md#tick-とシミュレーション時間)で表せることを検査する。

このデバイスへの入力は `TerminalInput(Bytes)` とし、回路へ送るバイト列をキューに追加する。送るデータがなければ `rx` を High にする。回路から受信したバイトとフレーミングエラーは、応答を待たない `TerminalOutput(Byte)` と `TerminalFramingError` でホストへ通知する。シリアルモニターの文字符号化と表示はホストが扱う。初期化と reset は送受信の途中状態と送信待ちキューを空にする。受信側は High を観測した後の立ち下がりを開始ビットの候補とする。
