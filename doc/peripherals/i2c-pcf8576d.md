# I²C 接続の7セグメント LCD

`i2c-pcf8576d` は [PCF8576D](https://www.nxp.com/docs/en/data-sheet/PCF8576D.pdf) を使った単一の静的駆動 LCD のモデルとして実装する。初版の対象は [キー行列と LCD の電卓](https://github.com/neknaj/circuitgame2/tree/main/examples/keypad-calculator) が使う書き込み経路である。I²C のバイト受信と ACK を決める処理から、LCD のコマンドと表示データの解釈を分ける。仕様の接続先は [標準デバイスの実装方針](../peripherals.md#デバイスの実装と接続)に従う。

## 回路との接続

| デバイス側ポート | ルート回路から見た方向 | 1ビットの意味 |
| --- | --- | --- |
| `scl-low` | 出力 | 1 で SCL を Low に駆動し、0 で解放する |
| `sda-low` | 出力 | 1 で SDA を Low に駆動し、0 で解放する |
| `scl` | 入力 | 合成した SCL のレベル。Low は 0、High は 1 |
| `sda` | 入力 | 合成した SDA のレベル。Low は 0、High は 1 |

`address` は7ビットの I²C アドレスを表す整数オプション。既定値は `0x38` で、SA0 に対応する `0x39` も指定できる。サブアドレスは0に固定する。ポートの不足や方向・幅の不一致と、範囲外のアドレスや未知のオプションは、起動前に設定の位置を持つ診断で報告する。

第 `t` tick の合成値には、前回確定した回路の `scl-low` と `sda-low`、および前回確定したデバイスの SDA 駆動要求を使う。いずれかの参加者が Low を要求した線は Low になる。このモデルは SCL を常に解放する。今回の遷移で決めた SDA 駆動要求は、次の tick の合成に使う。保持する前回の観測値は、初期化時と reset 時に両線 High とする。

## バイトと ACK

START は SCL が連続して High の間の SDA の立ち下がり、STOP は同じ条件での立ち上がりとする。START の後、SCL の立ち上がりで SDA を MSB から8回読む。データを読む立ち上がりの直前の tick には、SDA に同じ値が現れていることを前提とする。初版のコントローラーは各クロックの Low を2 tick 以上、High を1 tick 以上観測できるように駆動する。Low を2 tick 確保すると、立ち下がりを見て決めた SDA の駆動要求が、次の立ち上がりより前に合成値に現れる。

8ビット目を読んだ後の立ち下がりで、バイトを受け入れるかを決めて保持する。受け入れるなら SDA の Low を要求し、拒否するなら解放する。コントローラーは9クロック目までに SDA を解放し、9回目の立ち上がりで ACK（Low）または NACK（High）を読む。その立ち上がりを観測した tick の確定時に、保持した受け入れ判定に従ってバイトの変更を反映する。9クロック目の立ち下がりでデバイスは SDA を解放する。STOP では、どの受信段階でも確定前のバイトを破棄し、次の tick から SDA を解放する。初版が扱うのは、単一コントローラーの START から STOP までの書き込みである。SCL の Low が短い、データの立ち上がり前に SDA が安定していない、または9クロック目にコントローラーが SDA を解放していない場合は、当該バイトを破棄する。通信中の Repeated START も途中のバイトを破棄する。いずれの場合も、次の tick から STOP まで SDA を解放する。読み出しとクロックストレッチは対象外とする。 [I²C バス仕様 §3.1.3–3.1.6](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)

## LCD の静的駆動

START の後に `address << 1` と等しい書き込みアドレスを受け取ると ACK する。別のアドレスと読み出しには NACK を返し、STOP まで SDA を解放する。コマンド段階では、MSB の継続ビットが1なら次のバイトもコマンド、0なら次を表示データとして読む。下表のコマンドを受け付ける。初版のモデルは ACK できないコマンドや表示データを受け取った場合、STOP まで SDA を解放する。

| コマンド | 受理する値 | 反映する内容 |
| --- | --- | --- |
| mode-set | `0x41` または `0x49` に継続ビットを付けた値 | 静的駆動を選び、表示を無効または有効にする |
| device-select | `0x60` に継続ビットを付けた値 | サブアドレス0を選ぶ |
| load-data-pointer | `0x00`、`0x08`、`0x10`、`0x18`、`0x20` に継続ビットを付けた値 | 8列境界を指定する |

表示データ段階では、このトランザクションでポインターを指定済みで、静的駆動が選ばれ、残りの表示 RAM に8列分が入る場合に ACK する。受け入れたバイトは MSB から列 `P`〜`P+7` の BP0 に書き、ポインターを8進める。新しい START でポインターを未指定に戻す。駆動モード、表示の有効状態、RAM は STOP をまたいで保持する。モデルの RAM は BP0 の40ビットで、ポインター40に達した後のバイトを受け入れない。多重駆動、バンク切替、点滅、デバイスの連結は対象外とする。 [PCF8576D §6.10–6.12・§7.7](https://www.nxp.com/docs/en/data-sheet/PCF8576D.pdf)

四桁表示は RAM の列0〜31を左から8列ずつ使う。各桁の列順は `c b a f g e d dp` とする。表示無効時は全セグメントを消灯し、RAM の内容を保つ。シミュレーションの初期化と reset では、表示を無効にし、駆動モードと書き込みポインターを未指定にする。RAM は0で埋め、途中のバイトを破棄し、SDA を解放する。表示側は確定済みのセグメントを読み取る。このデバイスはホストイベントを受け取らず、要求や通知を発行しない。

## 実装で検査する例

- `0x70 0xc9 0xe0 0x00 0x00 0x00 0xd8 0x6e` を送る。8バイトすべての9クロック目が ACK になり、左から空白・空白・4・2を表すセグメントが確定する。
- `0x71` を送るとアドレスの9クロック目は NACK になる。表示データの8ビット目より前に STOP を送った場合も、先に確定した RAM と表示を保つ。8ビット目を読み終えた時点では表示を更新せず、有効な9回目の立ち上がりを確定した時点で更新する。
- 表示ビットが変わる tick を確定前に一時停止する。再開後に確定した SDA と表示は、そのまま実行した場合と一致する。中断して候補を破棄した場合は、最後の確定済みの表示を保つ。reset が成功すると全セグメントは消灯する。

このモデルが扱うのは合成した論理レベルと LCD の表示内容である。実機のクロック・データの絶対時間、電圧、表示の波形は、使う回路とデータシートで別途確認する。
