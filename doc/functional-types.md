# 関数型言語の構文と型検査

字句解析は[共通規則](grammar.md#字句)に従う。初版の関数は引数と戻り値がデータである一階の関数とする。呼び出し先は名前からコンパイル時に決まる。

## 補助関数

```lisp
(defn sum-nats ((xs (List Nat))) Nat
  (fold-list xs 0 (item acc) (add item acc)))
```

`(defn name ((parameter Type) ...) ResultType expr)` は関数を定義する。パラメーターは0個以上、結果式は1つとする。同じ関数のパラメーター名は一意とする。同じ名前空間の補助関数は掲載順に関わらず参照でき、引数の個数と型は宣言に一致させる。呼び出しグラフの循環はエラーとする。反復の本体やテンプレート内の `unsyntax`・`splice` の引数に現れる呼び出しもグラフに含める。テンプレートに書かれた回路の呼び出しは、展開後に回路言語の規則で検査する。

## 型と式

| 型 | 値 |
| --- | --- |
| `Bool` | `true`、`false` |
| `Nat` | 0以上、符号なし64ビット整数の最大値以下の整数 |
| `Int` | 符号付き64ビット整数で表せる整数 |
| `Symbol` | 名前を持つデータ |
| `Syntax` | 元の位置と束縛情報を持つ構文オブジェクト |
| `(List T)` | 要素の型がすべて `T` である有限リスト |

ホストの入口と組み込み関数は、状態やイベントなどの型を追加できる。追加した型の値は、入口の引数や、その型を扱うと宣言された組み込みから得る。型同士の暗黙変換は行わない。非負の十進リテラルは、期待型が `Int` ならその範囲を検査して `Int` とし、期待型が `Nat` または未定なら `Nat` とする。負のリテラルは `Int` とする。`(as-type T expr)` は期待型を明示するフォームであり、値の型を変換する操作は指定した組み込み関数で行う。

| フォーム | 受理条件 |
| --- | --- |
| `(if condition yes no)` | 条件は `Bool`。両分岐は同じ型とし、実行時は選んだ分岐だけを評価する |
| `(let ((name value) ...) body)` | 各値は左から元の環境で評価し、その結果を本体のローカル名に束縛する。同じ束縛列内の名前は一意とする |
| `(list expr ...)` | 全要素が共通の型を持つ。空のリストに期待型がなければ型注釈を要求する |
| `(fold-list xs init (item acc) body)` | `xs` は `(List T)`、初期値は型 `A`。本体では `item : T`、`acc : A` とし、結果も `A` とする |
| `(fold-nat n init (index acc) body)` | 回数は `Nat`。本体では `index : Nat`、`acc` は初期値と同じ型とし、結果もその型とする |

二つの反復の束縛名は互いに異なるものとする。0回の反復でも本体を型検査し、実行時には初期値を返す。型検査の期待型は、関数の引数・戻り値、型注釈、各フォームに定めた型から伝える。期待型のないリストでは、各要素の型が一意に決まる場合に共通型を求める。曖昧な場合は型注釈を要求する。

### 共通の組み込み

| 名前 | 引数と結果 | 実行時のエラー |
| --- | --- | --- |
| `add`、`sub`、`mul` | 同じ型の `Nat` 2個から `Nat`、または `Int` 2個から `Int` | 結果が型の範囲を越える |
| `eq` | 同じ型の `Bool`、`Nat`、`Int` または `Symbol` 2個から `Bool` | — |
| `lt` | 同じ型の `Nat` または `Int` 2個から `Bool` | — |
| `int-to-nat`、`nat-to-int` | 指定した整数型への変換 | 値が変換先の型の範囲を越える |
| `cons`、`is-empty` | 要素とリストからリスト、またはリストから `Bool` | — |
| `head`、`tail` | リストから先頭要素または残りのリスト | リストが空である |

複数の署名を持つ組み込みは、期待する結果型と、引数から分かる型に合う署名を選ぶ。数値リテラルだけが原因で `Nat` と `Int` の両方が候補になる場合は `Nat` を選ぶ。ただし負のリテラルや明示された `Int` は `Int` の署名だけに適合する。ほかの曖昧さには型注釈を要求する。

組み込みの失敗は言語の評価エラーとして扱う。エラーの種類と式の位置を保持し、値の代わりに呼び出し元に伝える。デバイスの入口が返す `Result` やテストの判定は、正常に評価された値として扱う。評価の一時停止と中断は[実行枠の規則](macros.md#一時停止再開中断)に従う。

## 実行段階と入口

回路ファイル内の `defn` と `defmacro` はマクロ段階の宣言とする。マクロは引数をすべて `Syntax`、結果を `(List Syntax)` として検査する。マクロ段階の `syntax` はテンプレート1個から `Syntax` を生成する。テンプレート内で `unsyntax` は `Syntax` を1個挿入し、`splice` はリストの要素位置で `(List Syntax)` を順に挿入する。構文の分解は `syntax-name` と `syntax-nat`、自然数からの構文生成は `nat-syntax` で行う。前二者は `Syntax` から `Symbol` または `Nat` を返し、対象が名前や自然数の構文でなければ評価エラーを返す。

デバイスとプロパティテストの実行環境は、関数名、段階、期待する型を入口として指定する。入口の宣言と型を照合してから実行する。デバイスの遷移関数の署名は[外部 I/O](memory-io.md#外付けインターフェイスの関数)に従う。補助関数も入口と同じ段階で検査し、推移的な呼び出し先まで、その段階に公開された名前と型だけを使える。デバイスの初期化や入口をプロジェクトに登録する記法は、各デバイスの型とともに定める。

型検査の検証では、型検査を通った式を、宣言どおりの値を持つ環境で評価すると、指定した型の値または規定した評価エラーに到達することを示す。各段階で使用可能な名前だけが解決されることも検証する。停止性と実行枠の合成は[マクロ仕様](macros.md#一時停止再開中断)に従う。
