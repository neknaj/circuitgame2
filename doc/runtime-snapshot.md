# 実行スナップショット

スナップショットは確定済みの tick から後で実行を再開するための保存データである。利用者が現在の tick を保存するか、現在の reset 世代でこれから到達する tick を指定する。指定した tick の更新と出力の確定を終えてから保存し、保存を指定していない tick では状態を複製しない。過去の tick は指定できない。指定時刻に達する前に reset または実行終了があれば、その指定では保存できなかった理由を返す。

保存処理に伴う短い遅延は許容する。状態を読み取る間に実行を待たせる実装もでき、その間は論理 tick とシミュレーション時刻を進めない。保存のための一時停止操作や専用の待機画面は要件としない。

## 保存する状態

- 回路の識別情報を格納する。復元先の配線配置、端子順、状態素子の種別と容量、実行条件の互換性を照合するために使う。
- 確定した tick 番号と reset 世代、設定された tick 周期、最後に適用した入力を保存する。公開出力はこの入力と確定した回路状態から復元する。ファイルに公開出力も含める実装では、復元時に導出した値と照合する。
- 全ゲートとラッチの出力、すべての RAM の全内容と確定した読み出し出力を保存する。read-first の RAM は書き込んだ tick の読み出し出力に更新前の語を出すため、この出力も独立して保持する。
- 入力の続きをランタイムが管理する場合は、次に適用する入力を特定できる位置と必要な時刻を保存する。例えば UART を転送の途中から再開するには、送り手の転送位置と次の送信時刻も必要になる。

最初の実装対象は外付けデバイスを使わない回路の実行である。外付けデバイス付きで復元できる環境を追加する場合は、デバイスの内部状態と待ちイベントを同じ tick 境界で保存し、復元で外部への要求が重複しない契約を用意する。未対応の構成を指定したときは保存または復元を拒否し、理由を返す。

## 保存先と形式

スナップショットにはバージョン付きの共通バイナリ形式を使う。同じ形式を CLI・デスクトップと Web のファイル入出力に使う。復号時はバージョン、回路の互換性、各フィールドの長さ、資源上限を確認する。保存データが主張する長さだけで領域を確保せず、復元先の回路構成と照合する。

ネイティブの実行環境では利用者が指定したファイルに保存する。同じディレクトリの一時ファイルへ全体を書き出して同期し、完了したファイルを保存先に置く。書き込みが失敗した場合は既存の保存を保持する。保存先に安全に確定できない環境ではエラーを返す。

Web 版は IndexedDB に本体と一覧表示に必要な情報を同じトランザクションで保存する。コミット後に保存完了を表示する。容量不足や利用できないストレージは診断し、ファイルのエクスポートとインポートも提供する。

## CLI と GUI での保存と再開

ネイティブの CLI では `ncg2 run --save-at <tick> <ファイル>` で保存する。続けて実行するときは、保存時と同じ回路と設定を使い、`--restore <ファイル>` と再開後の入力を渡す。復元直後の出力は保存した tick の出力で、その次の tick から新しい入力が適用される。[CLI の実行例](https://github.com/neknaj/circuitgame2-cli#実行を保存して再開する)

デスクトップ GUI では「Save snapshot…」でファイルに保存する。「Restore snapshot…」で同じ回路を読み込んだ状態に復元できる。復元直後は一時停止し、波形の記録を保存 tick から始める。入力スイッチを切り替えた直後に保存した場合も、保存されるのは最後に回路に適用した入力である。[GUI の説明](https://github.com/neknaj/circuitgame2-gui#スナップショットから再開する)

Web GUI では「Save in browser」で保存し、ページを開き直した後も「Saved snapshots」から選べる。「Restore selected snapshot」で再開する。別の端末や CLI へ渡すには「Download snapshot」でファイルを作る。ファイルの読み込みには「Restore snapshot」を使う。[Web GUI](https://neknaj.github.io/circuitgame2-gui/)

現行の保存と再開は外付けデバイスを使わない順序回路を対象とする。ファイルは保存した回路と配線、端子配置、tick 周期が一致する実行先で使う。

## 証明と結合テスト

Core で次の性質を証明する。

1. 保存対象は単一の確定済み tick の状態であり、保存によって元の実行状態は変わらない。
2. 適合する回路へ保存結果を復元すると、ゲート、状態素子、RAM の内容と読み出し出力が一致する。最後の入力で観測した公開出力も保存時と一致し、次の更新は保存した tick の次から始まる。
3. 復元した実行と中断しなかった実行に同じ残りの入力列を与えると、各 tick の状態、公開出力、RAM が一致する。保存時に決定済みの次の入力がある場合は、その入力から再開する。
4. 不適合な回路や状態を拒否し、失敗時に復元先の状態を保つ。符号化と復号は全ての有効な保存状態で往復でき、不正な長さやバージョンを拒否する。

ファイル書き込みの中断や容量不足、IndexedDB トランザクションの失敗、別プロセスでの再起動は対応するホストの結合テストで確認する。
