# メモリとルート回路の入出力

## 内蔵 RAM とプログラム可能なメモリ

内蔵の `memory` は、回路内で使う固定仕様の同期 RAM である。1つのアドレスで1語を読み書きする。毎 tick の開始時に `address`、`data`、`write-enable` を読み、終了時に読み出し出力と記憶内容を同時に確定する。`write-enable` が1の tick は毎回書き込む。同じ tick に読んで書くと、出力は更新前の値になる。この規則を read-first と呼ぶ。reset で記憶内容と読み出し出力を初期値に戻す。初版の初期値は全て0である。

| tick 開始時の値 | tick 終了時の読み出し出力 | tick 終了時の対象語 |
| --- | --- | --- |
| アドレス3の内容が `0x12`、書き込み許可が1、書き込み値が `0x34` | `0x12` | `0x34` |
| 次の tick でもアドレス3、書き込み許可が0 | `0x34` | `0x34` |

外付けメモリは[純粋関数型言語](macros.md#外付けインターフェイス)で記述できる。アドレス、データ、制御信号をどう解釈するか、読み出し・書き込み・消去の条件、待ち時間、アドレス範囲外の応答、reset の効果を、デバイス自身の状態遷移として定義する。例えば、揮発性のテスト用 RAM は内容も状態として持てる。フラッシュやファイルを使うメモリは、ホストへの要求と応答によって内容を管理する。大きな試験用 RAM でも、状態の意味論に従う範囲で実装は配列の全コピーを省ける。

## main のポートへの割り当て

通常は `main` を実行するルートモジュールとして選ぶ。別のルートを使う場合は実行設定で選択する。外部から扱うピンは、選択したモジュールが宣言した名前付きの入出力ポートである。1ビットの信号も複数ビットのバスもポートとして扱う。接続の記述は実行設定に置く。同じ `main` にテスト用メモリと実際に永続化するメモリを差し替えられる。

| 接続 | デバイス側の操作 |
| --- | --- |
| `main` の `out` | 確定した出力値を読む。複数のデバイスが同じ出力を観測できる |
| `main` の `in` | 次に適用する入力フレームの値を決める。各入力ポートに駆動元を1つ割り当てる |

初版はポート単位で名前を対応させ、方向と型・ビット幅の一致を検査する。入力への重複接続はエラーとし、未接続の入力は実行環境が与える入力フレームで扱う。デバイスへの割り当てがあるポートをテストや UI から直接駆動する場合は、その実行の接続設定で入力源を切り替える。

例えば8ビットデータのフラッシュ読み出し口は、次のように割り当てられる。方向は `main` から見た方向である。

| `main` のポート | デバイスのポート | 方向と幅 |
| --- | --- | --- |
| `mem-address` | `address` | `out` 16ビット |
| `mem-req-valid` | `req-valid` | `out` 1ビット |
| `mem-req-ready` | `req-ready` | `in` 1ビット |
| `mem-rsp-valid` | `rsp-valid` | `in` 1ビット |
| `mem-rsp-data` | `rsp-data` | `in` 8ビット |
| `mem-rsp-error` | `rsp-error` | `in` 1ビット |
| `mem-rsp-ready` | `rsp-ready` | `out` 1ビット |

書き込みや消去を扱うデバイスは、操作種別と書き込みデータを要求チャネルに追加する。

## tick ごとの受け渡し

tick `t` の開始時に、デバイスは tick `t-1` の終了時に確定した回路出力と、今回受け取ったホストイベントを読む。デバイスが算出した入力フレームと確定済みの回路出力を使い、要求側と応答側それぞれで `valid == 1` かつ `ready == 1` なら転送が成立する。送信側は成立まで `valid` とデータを保持する。tick `t` で受理した要求の応答は、最短で tick `t+1` の入力に載る。回路出力が tick `t` の終了時に変わった場合、その値をデバイスが読むのは次の tick である。

| tick | フラッシュ読み出しの例 |
| --- | --- |
| `t` | 確定済みの出力で `mem-req-valid = 1`、今回の入力で `mem-req-ready = 1`。メモリがアドレスを受理し、tick 確定時に読み出し要求をホストへ渡す |
| `t+1` | 応答データが利用可能であれば `mem-rsp-valid = 1` とデータを入力に載せる。回路の確定済みの `mem-rsp-ready` が0なら転送は成立せず、デバイスは応答を保持する |
| `t+2` | `mem-rsp-ready = 1` になった場合、保持していた応答の転送が成立する |

reset 時はポートの初期値、未処理要求と応答の扱い、揮発性状態の初期化をデバイス仕様で定める。上の例では reset で未処理要求と保持中の応答を破棄し、次の入力フレームでは受付可能・応答なしを返す。reset 前の要求に対して遅れて届いた応答は要求 ID と reset の世代で識別し、回路入力へ反映しない。確定済みの永続化操作はホストのデバイス仕様に従う。

検証では、内蔵 RAM の同アドレス読み書き、接続後の入力の単一駆動、転送待ちで応答が保持されること、reset 前の応答が混入しないことを扱う。read-first は [AMD の RAM 同期モード](https://docs.amd.com/r/2025.1-English/ug901-vivado-synthesis/Block-RAM-Read/Write-Synchronization-Modes)にも見られる。要求・応答に用いるハンドシェイクは [Arm の AMBA AXI 仕様](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/IHI0022H_amba_axi_protocol_spec.pdf)を参考にした。
