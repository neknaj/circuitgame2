# 増分解析の検証条件

同じ解析スナップショットに対して、増分解析とキャッシュを使わない解析が同じ結果を返すための条件を示す。比較する問い合わせと解析段階はそろえ、診断、補完、定義位置に加えて構文エラーの回復結果と未解決の参照も比較する。妥当な入力では共通の解析対象について厳格なコンパイラ解析との一致も示す。[検証設計](../verification.md#編集単位の増分解析)・[言語サービスの実装方針](../development.md#編集単位の増分解析)

## 接尾部を再利用できる条件

字句や構文の局所再解析では、再開位置までの結果が維持されることを示す。未変更の接尾部に合流する位置では字句と構文の継続状態を照合する。回復中の未確定な構文も比較に含める。再利用した範囲が新しい版で同じテキストを指すことも示す。

## 依存が同じときに結果を再利用できる条件

問い合わせには文書、位置、解析段階などの引数を識別するキーを与える。スナップショットに依存する値を読む処理は、型とモジュール境界で依存追跡付きの API に限る。各読み取りは一つのスナップショットに対して行い、依存キーと観測値を記録する。確定時の依存集合がその計算で実際に行った全読み取りを覆うことを示す。

同じ問い合わせキーと同じ読み取り列の接頭部から、次に読む依存キーまたは最終結果が一意に決まることを示す。これにより、記録した観測値がすべて等しいスナップショットでは、読み取り列と結果も等しいと導ける。依存には設定、ソース集合、宣言の候補集合と候補の不存在、未解決の名前を含める。

問い合わせの外の可変状態を入力に使う場合は、スナップショットへ固定して同じ API で読む。問い合わせが観測する走査順と結果の並び順はソース順や名前順などの規則で定める。ハッシュ表を使う場合も、ハッシュのシードや内部の走査順によって読み取り列や結果が変わらないようにする。

## 結果の確定と中断

実行中の問い合わせは作業状態に結果と依存を蓄える。完了した結果と依存集合は一つの操作でキャッシュに登録し、中断した問い合わせの作業状態は破棄する。外側の問い合わせを中断しても、内側の問い合わせが完了して結果と依存を確定済みなら、独立した項目として保持できる。

新しいスナップショットで再利用する前に項目の依存を照合する。依存先が別の問い合わせなら、その依存先について再利用条件を確認した結果か、再計算した結果を照合に使う。キャッシュに入るのは、計算時のスナップショットに対する契約を満たす完了済みの項目だけであることを示す。

## 編集列を使う検証

固定シードで作った編集列を適用し、各編集後の結果を、その版からキャッシュを使わずに求めた結果と比較する。括弧や引用符の削除、宣言の改名・追加、未解決の参照の解消、問い合わせの途中での中断と次版での再計算を含める。外側の問い合わせを、内側の問い合わせだけが完了した時点で中断する。次版で内側の依存が同じ場合と変わる場合を調べる。失敗時は初期入力、編集列、中断位置、シードを保存する。

ホストとの結合テストではプロトコル経由の複数編集の順序、取り消し、公開時の文書版の照合を確かめる。
